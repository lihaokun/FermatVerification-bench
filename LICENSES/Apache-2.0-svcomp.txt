SV-COMP characteristics:
  - Each program is small (typically < 100 LOC)
  - Uses `__VERIFIER_*` extern functions (nondet_int, assume, error)
  - `__VERIFIER_assert(P)` calls express the verification goal inline
  - Companion `.yml` files declare which properties to verify (unreach-call,
    termination, no-overflow, valid-memsafety, etc.) and expected verdict
  - NOT C+ACSL (no /*@ ... */ blocks); goals are in C asserts and YAML

Our bench storage convention:
  - `ground_truth.c` = upstream .c verbatim (no ACSL, hence stripped.c == ground_truth.c)
  - `strip_lines = []`, `goal_type = "rte_only"`
  - SV-COMP property metadata (from .yml) recorded in case.toml notes
